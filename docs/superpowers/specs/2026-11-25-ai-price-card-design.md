# AI 2주 가격 카드와 질문 답변 모델 재배치 설계

- 작성일: 2026-11-25
- 상태: 개발자 승인 대기
- 영향 문서: `docs/finguard_ai_prd_v3.8.md`(1.1, 3.1, 5.1, 6, 7절), `CLAUDE.md`, `AGENTS.md`(있으면), `README.md` 모델 배치도

## 1. 의도

사용자가 원하는 것은 **종목을 검색하면 AI가 차트·뉴스·공시를 함께 읽고 단기 저점과 단기 고점을 알려 주는 카드**, 그리고 **내 계좌와 그 종목 자료를 보고 내 질문에 직접 답하는 채팅**이다.

현재 구조는 이 목적에 비효율적이다.

- Qwen 3.7-plus(가장 똑똑한 모델)는 질문을 세 종류로 분류만 한다. 분류는 이미 정규식으로도 동작한다.
- Qwen 3.8-flash 워커가 종목별 위험 분석문을 쓰지만 종합 단계·화면 어디에서도 읽지 않는다.
- 워커가 가져온 뉴스도 버려진다.
- 가격 카드의 가격은 20일 최저·최고·평균 변동폭만으로 계산되고, Gemini는 공시 기반 이유 문장만 붙인다.
- 채팅 LLM은 질문 원문을 받지 못해 "추가매수할까?" 같은 질문에 답할 수 없다(PRD 3.1).

## 2. 목표 / 비목표 / 실패 조건

**목표**

1. 종목을 검색하거나 선택하면 **Qwen 3.7-plus**가 차트 지표·수급·뉴스·공시를 분석해 **2주(10거래일)** 단기 저점·단기 고점·2주 상단 가격과 카드 아래 짧은 설명을 자동으로 만든다.
2. AI가 정한 가격은 모두 출처 번호를 달고, 코드가 검증한다. 검증에 실패한 가격은 로컬 계산값으로 대체하고 화면에 표시한다.
3. 채팅 질문에는 **Qwen 3.8-flash**가 계좌·해당 종목 카드·종목 자료·질문을 읽고 직접 답한다.
4. **Gemini 3.8-flash**는 평소 호출하지 않는다. DashScope 장애 시 대체 모델, 그리고 Module 8 채점(Judge) 전용이다.
5. 매일 카드 결과를 기록하고 10거래일 뒤 적중률을 계산해, AI 카드가 로컬 계산보다 나은지 수치로 확인한다.

**비목표**

- 자동 주문, 장중 분 단위 예측, 해외 종목.
- 화면 디자인 전면 개편(기존 가격 전망 카드와 채팅 UI를 확장한다).

**실패 조건 (동작해도 실패로 본다)**

- 화면에 출처 없는 AI 숫자가 그대로 노출된다.
- AI 장애 때 카드나 채팅이 빈 화면으로 끝난다(로컬 결과 + 경고가 항상 나와야 한다).
- 채팅이 "반드시 사라/팔아라" 같은 확정 지시를 한다. 조건부 판단(예: "20일선 회복 전까지는 보유 기준")은 허용한다.
- 계좌번호·API 키·토큰이 외부 LLM으로 나간다.

## 3. 제약 (기존 규칙 중 유지)

- 금액·수량·비중 계산은 `Decimal`만 사용. LLM이 낸 가격 문자열도 `Decimal`로 파싱해 검증한다.
- Uvicorn `workers=1`, 임베딩·리랭킹은 `gpu_semaphore(1)`.
- `fastembed` 금지, `overhang_events`·`stock_master` 규칙 유지.
- LLM 전면 장애에도 SSE는 `status → token → done(ok=true)`로 끝난다.

## 4. 검토한 방식

| 방식 | 내용 | 장단점 | 결정 |
|---|---|---|---|
| A. 로컬이 가격, AI는 후보 선택·설명 | Python이 후보 가격을 내고 AI는 고르기만 | 숫자 안전성 최고. AI 판단 폭이 좁음 | 미채택 |
| B. 대화형 에이전트 | Qwen 3.7-plus가 도구를 직접 호출해 질문에 답 | 가장 유연. 느리고 비싸며 숫자 통제 어려움 | 미채택 |
| **C. AI가 가격까지 결정 + 출처·검증** | Python이 지표와 자료에 번호를 붙여 주고 AI가 가격·설명을 정함. 코드가 출처·범위·순서를 검증 | AI 판단을 살리면서 지어낸 숫자를 차단. 검증기 구현 필요 | **채택 (개발자 선택)** |

답변 모델은 Qwen 3.8-flash와 Gemini 3.8-flash를 비교했다.

- Qwen 3.8-flash는 Gemini보다 비용이 약 5~8배 싸다. 첫 글자 지연도 더 짧다(OpenRouter 중앙값 0.73초 대 2.81초).
- 지능 지표 차이는 작다(28.6 대 30.8).
- 무거운 분석은 카드 단계에서 이미 끝나므로 답변은 flash급이면 충분하다.
- **결정:** 답변은 Qwen 3.8-flash가 맡는다. Gemini는 장애 대체와 채점 전용으로 유지한다. 공급사 이중화를 지키고, 같은 계열 모델이 자기 답을 채점하는 문제를 피하기 위해서다.

## 5. 모델 배치 (개발자 결정)

| 역할 | 모델 | 환경변수(제안) | 입력 | 출력 |
|---|---|---|---|---|
| 가격 카드 분석가 | `qwen3.7-plus` | `ANALYST_MODEL` | 지표 [P-n], 수급, 뉴스 [NEWS-n], 공시 [DOC-n], (보유 시) 평단가·비중·수익률 | 저점·고점·상단 가격, 근거 번호, 이유, 카드 설명, 이벤트 위험 |
| 질문 답변 | `qwen3.8-flash` | `ANSWER_MODEL` | 질문 원문, 계좌 요약, 대상 종목 카드, 종목 자료, 로컬 시뮬레이션 결과 | `### 핵심 답변` / `### 판단 근거` 리포트 |
| 장애 대체 | `gemini-3.8-flash` | `FALLBACK_MODEL` | 위 두 역할과 같은 입력 | 같은 출력 |
| 채점(Judge) | `gemini-3.8-flash` | `JUDGE_MODEL` | Module 8 평가 데이터 | RAGAS 점수 |

- 기존 `ROUTER_MODEL`·`WORKER_MODEL`·`SYNTHESIZER_MODEL`은 제거한다. LLM 라우터는 없애고 로컬 정규식 분류만 쓴다.
- 장애 전환은 DashScope의 429·403·할당량 오류와 시간초과·5xx에서 Gemini로 한 번 전환한다. Gemini도 실패하면 로컬 결과를 낸다.

## 6. 가격 카드

### 6.1 흐름

1. 종목 선택 → 기존처럼 **로컬 계산 카드를 즉시** 보낸다(`price_bands` 이벤트). 화면이 비지 않게 하기 위해서다.
2. 백엔드가 지표·자료를 모아 분석가를 호출한다.
3. 검증을 통과한 결과로 카드를 갱신한다(`done` 이벤트).
4. 결과를 캐시와 적중률 기록에 저장한다.

- 분석가는 기존 `enrich_bands`의 Gemini 이유 문장 단계를 **대체**한다.
- 화면은 단일 종목 모드(`target_stock_code`)만 호출한다. 전체 보유 종목 모드(`price_band_updates`)는 로컬 계산만 남긴다. *(설계자 판단: 화면에서 쓰지 않는 경로에 보유 종목 수만큼 3.7-plus를 호출하지 않기 위해서다.)*

### 6.2 분석가에게 주는 재료

모든 재료에 번호를 붙인다. 숫자 재료는 `[P-n]`이고 라벨·값·날짜를 함께 준다.

- **일봉:** 최소 80거래일(60일선 계산용). 지금 `end-60일` 조회는 약 40거래일이라 부족하다. 달력 기준 약 120일 이상으로 늘린다.
- **이동평균:** 5일·20일·60일선.
- **단기 저점·고점:** 최근 60거래일 스윙 저점·고점. 현재가 아래와 위로 가까운 순서대로 각 최대 3개, 날짜를 포함한다.
- **매물대:** 최근 60거래일 종가를 가격 구간별로 나눠 거래량을 합산한 상위 3개 구간.
- **변동성:** ATR14(평균 실제 변동폭).
- **현재가와 기준일, 최근 5거래일 외국인·기관 순매수.**
- **뉴스 `[NEWS-n]`:** 네이버 뉴스 최대 10건(제목·요약·날짜). 기존 `get_news`를 재사용한다.
- **공시 `[DOC-n]`:** 최근 60일 DART RAG 상위 3건. 기존 `DISCLOSURE_QUERY`와 별칭 체계를 재사용한다.
- **보유 종목이면 추가 재료:** 평단가, 비중, 수익률.

### 6.3 분석가 출력 스키마

```
levels:
  low:     { price: "정수 문자열", basis: ["P-2", ...], reason: "한 문장, 근거 번호 포함" }
  high:    { ... }   # 단기 고점(차익 실현 검토)
  ceiling: { ... }   # 2주 상단(넘기 어려운 가격)
summary: "카드 아래 2~3문장 설명, 근거 번호 포함"
risks:   [ { text: "실적 발표 예정 등", basis: ["NEWS-4"] } ]   # 0~3개
citations: [...]
```

### 6.4 검증 규칙 (레벨별로 따로 적용)

1. **형식:** 양의 정수이고 `Decimal`로 파싱돼야 한다. KRX 호가 단위로 반올림한다.
2. **순서:** `low ≤ 현재가 ≤ ceiling`이고 `low < high ≤ ceiling`이어야 한다. 순서가 깨지면 세 레벨 모두 로컬 값을 쓴다.
3. **범위:** `|가격 − 현재가| ≤ 4 × ATR14`. 계수는 적중률 기록을 보고 조정한다.
4. **근거:** `basis`에 실제 존재하는 `[P-n]`이 하나 이상 있어야 한다. 가격이 인용 지표값에서 `max(1 × ATR14, 3%)`보다 멀면 `reason`에 `[NEWS-n]`이나 `[DOC-n]` 인용이 있어야 한다. `2 × ATR14`를 넘게 벗어나면 거부한다.
5. **인용:** 존재하지 않는 번호나 14자리 공시번호가 들어간 문장은 버린다. 기존 `ALIAS`·`RECEIPT` 검사를 재사용한다.
6. **이유·설명 문장의 숫자:** `원·주·%`가 붙은 숫자는 재료에 있는 값과 일치할 때만 허용한다. 일치하지 않는 문장은 버린다.
7. **실패 처리:** 실패한 레벨만 기존 `calculate_market_band` 값으로 대체하고 `source: "local"`을 표시한다. 통과한 레벨은 `source: "ai"`다.

### 6.5 화면

- 라벨: `2주 상단` / `단기 고점 (차익 실현 검토)` / `현재가` / `단기 저점 (매수 검토)`.
- 각 레벨에 `AI` 또는 `기본 계산` 배지를 붙인다.
- 카드 아래에 `summary` 설명을 표시한다. 이벤트 위험이 있으면 목록으로 보여 준다.
- 판단 근거 영역에 60일선, 스윙 저점·고점, 매물대, ATR을 추가한다. 인용된 뉴스는 원문 링크로, 공시는 DART 링크로 연결한다.

### 6.6 캐시

- 백엔드 Redis에 `종목코드 + 기준 거래일` 키로 검증된 카드를 저장한다. 채팅이 재사용하기 위해서다.
- 장중에는 짧게(예: 10분), 장 마감 후에는 다음 거래일 개장 전까지 유지한다. 정확한 TTL은 빌더가 정한다.

## 7. 질문 답변 (채팅)

### 7.1 흐름 (LangGraph 골격 유지, 노드 역할 변경)

1. **router_node:** LLM 호출 없이 로컬 정규식만 쓴다. 의도(단순 조회/시뮬레이션/분석)와 질문 유형(추가매수·홀드·손절·목표가 등)을 분류한다.
2. **market_data_node → quant_scorecard_node:** 기존과 같다. 시뮬레이션 의도면 로컬 시뮬레이터를 돌린다.
3. **fan_out → stock_worker:** 대상 종목마다 **카드를 가져온다**. 캐시가 있으면 쓰고, 없으면 6장의 분석가 흐름을 실행한다. 대상이 0개면 `"synthesizer_node"`를 반환한다(기존 규칙 유지).
   - **대상 종목 결정 순서:** ① 채팅 요청에 함께 보낸 현재 선택 종목 코드(신규 선택 필드) ② 질문에 언급된 보유 종목 ③ 둘 다 없으면 비중 상위 3종목.
4. **guardrail_node:** 카드 검증 결과를 `verified_stock_results`에 기록한다. 리듀서는 추가하지 않는다.
5. **synthesizer_node:** **Qwen 3.8-flash**가 답변을 생성한다. 이어서 문장 단위 인용 검증과 숫자 검증(아래 7.3)을 한 뒤 스트리밍한다. 실패하면 Gemini, 그것도 실패하면 로컬 `diagnosis_report`를 쓴다(2026-11-25 추가된 조건부 판단 포함).

- 기존 워커의 위험 분석문 LLM 호출은 제거한다.
- 캐시된 카드가 없으면 채팅은 카드 생성이 끝날 때까지 기다린다. 이 동안 종목별 `status` 이벤트("가격 카드 분석 중")를 보낸다. 분석가가 실패하면 그 종목은 로컬 카드로 진행한다. *(설계자 판단: 카드와 채팅이 같은 숫자를 말하게 하기 위해서다.)*
- 단순 조회(`fast_lookup`) 경로는 지금처럼 LLM 없이 처리한다.

### 7.2 답변 모델 입력 (PRD 3.1 개정, 개발자 결정)

- **보내는 것:** 질문 원문, 종목별 이름·코드·수량·평단가·현재가·비중·수익률, 예수금·총평가액, 대상 종목의 검증된 카드(가격·근거·설명·위험), 재료 `[P-n]`·`[NEWS-n]`·`[DOC-n]`, 로컬 시뮬레이션 결과.
- **보내지 않는 것:** 계좌번호, 증권사·외부 API 키와 토큰, PIN, 기타 자격증명.

### 7.3 답변 검증

- 기존 형식 검사(`### 핵심 답변` / `### 판단 근거`)와 `[DOC-n]` 문장 단위 Drop을 유지한다. `[NEWS-n]`·`[P-n]`에도 같은 방식을 적용한다.
- `원·주·%`가 붙은 숫자는 입력에 있는 값과 일치해야 한다. 일치하지 않는 문장은 Drop하고 경고를 단다. 평단가 재계산 같은 산술은 LLM이 하지 않고, 로컬 시뮬레이션 결과를 인용하게 한다.
- 프롬프트 원칙: 질문에 대한 조건부 판단을 첫 문장에 쓴다. 확정 지시는 금지한다.

## 8. 적중률 기록과 평가

- **저장:** Postgres 신규 테이블. 종목, 기준일, 현재가, 레벨별 가격과 `source`, 모델명, ATR14, 같은 날 로컬 계산 값을 저장한다. 같은 종목·기준일은 한 행만 둔다(최신 결과로 갱신).
- **채점:** 10거래일이 지나면 실제 고가·저가로 다음을 계산한다. 실행 방식(스크립트 또는 주기 작업)은 빌더가 정한다.
  - 저점 유지: 기간 최저가 ≥ low × (1 − 1%)
  - 고점 도달: 기간 최고가 ≥ high
  - 상단 유지: 기간 최고가 ≤ ceiling
  - 각 지표를 AI 카드와 로컬 카드로 나눠 비교한다.
- **답변 모델 비교 (Module 8 확장):** 기존 20건 데이터셋으로 Qwen 3.8-flash와 Gemini 3.8-flash의 답변을 생성한다.
  - 1차 지표는 숫자 오차율(결정론 검사)과 Faithfulness이고, 판정이 비슷하면 지연시간·비용으로 확정한다.
  - Judge가 Gemini라 Gemini 답변에 유리할 수 있다. 결정론 지표를 우선한다.
